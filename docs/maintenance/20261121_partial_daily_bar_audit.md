# 장중 일봉 사용 범위 감사 — 2026-11-21

Base: `32541f3a`. Offline, fixed-input audit only. No application source, score,
decision label, TTL, price routing or partial-bar policy changed.

## 결론

**판정의 장중 봉과 확인축·A/B/C의 완료봉은 서로 다른 목적이다.** 두 입력에서 이 구분은
재현됐고, 시황 함수도 완료 종가와 장중 관측을 분리했다. 이를 무조건 같은 마지막 봉으로
통일하면 기존 RSI·ATR·손익비가 바뀐다. 별도로 날짜 표시의 모호함과 특수장 달력 불일치를 발견했다.

| 입력 / 소비 경로 | 사용 범위 | 가격 | 의미 |
| --- | --- | --- | --- |
| 379810 판정 | 245봉, 11/20까지 | 입력·원자료 모두 23,180 | 한국장 마감 후 캡처 |
| 379810 확인축·A/B/C | 245봉, 11/20까지 | 23,180 | 완료 거래일 관측 |
| 379810 시황 함수에 같은 원자료 주입 | 245봉, 11/20까지 | 23,180 | 함수 비교만 수행; 실제 보고서는 별도 정규종가 공급 경로 사용 |
| GOOGL 판정 | 252봉, 11/20 장중 포함 | 원자료 279.9100 / 선택 시세 279.9452 | 지표는 원자료, 현재 가격 입력은 별도 시세 |
| GOOGL 확인축·A/B/C | 251봉, 11/19까지 | 272.6600 | 11/20 미완료 봉 제외 |
| GOOGL 시황 완료 종가 | 251봉, 11/19까지 | 272.6600 / 일간 -3.4627% | 완료 종가 표 |
| GOOGL 시황 장중 관측 | 11/20 봉 | 279.9100 / 일간 +2.6590% | `장중 진행·확정 아님`으로 별도 표시 |

확인축 표는 구조·가격 위치·기간·유동성 대용치이며 RSI/ATR를 새 점수로 매기는 곳이 아니다.
아래 완료봉 RSI/ATR는 영향을 분리해 보기 위한 감사 계산이다.

## 동일 입력과 수치 재현

보존 ZIP의 OHLCV를 `float_precision=round_trip`으로 읽고 attrs를 복원했다.
현재 시각이나 새 시세를 사용하지 않고 저장된 `계산시각`의 명시적 KST를 사용했다.

| 입력 | 고정 계산 시각(KST) | 가격입력ID | 완료 거래일 |
| --- | --- | --- | --- |
| 379810.KS | 2026-11-21 01:08:41 | bf23c77900eefde6 | 2026-11-20 |
| GOOGL | 2026-11-21 00:36:10 | e4f3a675caffbd4d | 2026-11-19 |

두 입력 모두 ID가 일치하고 저장된 **현재가·RSI·ATR·원자료 일간 등락·R/R 5개 값**이
허용 오차 1e-10에서 재현됐다. 저장된 A/B/C의 완료 거래일과 가격도 각각 일치했다.
이는 전체 판정 함수 재실행이 아니다. 외부 RS·재무·계좌 입력까지 재현했다는 뜻은 아니다.

| 입력 | 기존 원자료 RSI → 완료봉만 RSI | ATR 비교 | 같은 시세·저장 목표가에서 R/R 비교 |
| --- | --- | --- | --- |
| 379810.KS | 30.353392 → 30.353392 | 587.142857 → 587.142857 | 1.686131 → 1.686131 |
| GOOGL | 36.838639 → 30.579554 | 10.818564 → 10.657137 | 1.156570 → 1.174086 |

R/R 민감도는 선택 시세와 기존 내부고점 목표가를 고정하고 ATR 입력만 바꿨다.
새 구조 고점·후보 등급·게이트를 재계산하지 않았으며, 완료봉 R/R은 실제 A/B/C의 가격비율이 아니다.
GOOGL 시세와 원자료 차이는 약 0.0126%로 기존 0.3% 보정 임계값보다 작다.
현재 구현은 이때 가격 시세를 선택하면서 OHLC 지표 봉은 보정하지 않는다. 이번에 바꾼 규칙이 아니다.

## 근거 코드와 분류

- **의도된 차이:** `decision_inputs.prepare_decision_price_inputs` / `decision_engine`
  latest row 경로는 공급된 장중 봉을 자동 제외하지 않는다. `calc_atr_for_decision`은
  `source_price_rows`로 단일 시세 덮어쓰기를 복원/제외하지만, 공급처 일봉을 완료봉으로 인증하지 않는다.
- **의도된 차이:** `chart_structure.latest_completed_chart_session`은 거래소 달력을 사용한다.
  `scenario_evidence.completed_scenario_frame`은 그 날짜 이후와 `LiveQuoteOnly`를 제외한다.
  `precision_scenarios._attach_completed_observations`는 완료봉 관측을 붙이고 기존 실행 제한을 유지한다.
- **의도된 차이:** `report_evidence.price_observation`은 완료 종가용,
  `intraday_observation`은 장중용이다. 후자는 명시적으로 미확정 라벨을 붙인다.
  `report_context`의 KR 경로는 `kr_regular_history.align_regular_frames`로 별도 정규종가를 읽는다.
- **표시 개선 필요:** GOOGL의 +2.6590%는 11/20 장중 대비 11/19 종가인데 저장된
  `day_ret_label`은 `전일등락`이다. `live_price_used=False`는 완료봉 인증이 아니라 보정 여부에
  가까운 기존 플래그다. 숫자 오류와 구분하고, 계산일/세션 설명을 보완할 대상으로 남긴다.
- **실제 달력 불일치:** `report_session.market_session_states`,
  `report_evidence.closed_daily_frame`, `market_board.completed_close_series`는 일부 경로에서
  고정 정상장 시간을 사용한다. 같은 코드에 등록된 특수장 달력과 일치하지 않는다.

## 특수장 경계 재현과 영향 범위

계좌 자료 없이 만든 합성 봉과 **2026-11-19 16:00 KST**를 사용했다.
앱의 기존 `_exchange_schedule`에는 이 날 KR 마감이 16:30으로 등록돼 있다.

| 소비 경로 | 현 결과 | 해석 |
| --- | --- | --- |
| 거래소 달력 / 확인축 | 완료 거래일 11/18 | 아직 장중 |
| 시황 세션 상태 | closed | 고정 15:30 적용으로 조기 마감 표시 |
| 단순 시황 종가 필터 / 보드 | 11/19 포함 | 실제 특수장 마감 전인데 포함 |
| 별도 KR 정규종가 수집기 | 11/18까지만 허용 | 실제 마감+15분 필터가 정상 경로를 보호 |

따라서 이 한계를 **이번 379810 운영 종가가 오염됐다는 증거로 확대하지 않는다**.
두 실제 캡처는 이 경계 밖에 있다. US 보고서의 15분 완료 버퍼와 확인축의 실제 마감시각 차이는
의도된 대기 정책이며, 휴장/특수장 달력을 무시하는 문제와 다르다.

## 산출물과 검증 범위

- `scripts/audit_daily_bar_consumers.py`: JSON/CSV 고정 입력만 읽고 네트워크를 차단한다.
  기존 출력 파일을 덮어쓰지 않는다. 입력ID 불일치·시각 형식 오류·시세 덮어쓰기 사례는 범위 밖으로 거부한다.
- 실제 입력: Downloads의 `precision_review_379810.KS (4).zip`,
  `precision_review_GOOGL (34).zip`. 원본은 수정하지 않았다.
- 결과: ignored `cache/operating_20261121/partial_bar_consumer_audit.json`.
  입력 SHA256과 숫자 비교만 저장하며 개인 계좌 입력은 진단 출력에 포함하지 않는다.
- 이번 운영 검증의 범위는 **보존된 운영 입력의 로컬 재현**이다. 새 운영 계산·보고서 생성·리부트는
  실행하지 않았다. 국내 보고서 별도 공급 응답 전체가 이 ZIP에 없어 동일 시점의 전체 보고서 인증은 불가능하다.
- 기존 입력·판정 입력·확인축·시황·신선도·KR 정규종가 관련 **344 passed**, 32.66s.
  기존 scenario_evidence의 pandas FutureWarning 2건은 기록만 하고 이번 범위를 넓히지 않았다.
- 새 고정 입력 감사 테스트 **11 passed, 1 xfailed**, 6.94s. xfail은 위 특수장 결함을
  올바른 기대값으로 재현하는 `strict=True` 테스트다. 해결되면 xfail 표시를 제거해야 한다.
  전체 기능 통과나 결함 해결로 세지 않는다. 합성 입력만 Git에 저장했다.
- 입력 변조·시각 누락·덮어쓰기·네트워크 요청을 거부하고, 저장 수치 불일치는 진단 결과와
  실패 종료코드로 남기는지 검증했다. 기존 출력/ZIP 불변성도 확인했다.

실행 예: `.venv311/Scripts/python.exe -X utf8 scripts/audit_daily_bar_consumers.py
<379810-review.zip> <GOOGL-review.zip> --output cache/<new-output>.json`.
