# C-6/C-11 2단계: 계좌 범위·명시 비중·신호 미확인·항상투자 (2026-11-26)

사용자 결정(2026-11-26 09:14 KST) 3·4·5·8항의 2단계입니다. 네 가지를 고쳤고, 항목별 결과 차이는 아래에 따로 적었습니다.
판정 엔진 규칙, 게이트, 배율표, L3 규칙은 바꾸지 않았습니다.

## ① 월적립 신호 캐시의 계좌 범위 표시
- 바꾼 것: 자산관리의 신호 계산 시 `_ticker_signal_cache_context`에 계좌 범위(`portfolio_signal_input_context`)를 함께 저장합니다.
  월적립 계산기는 저장된 범위와 현재 범위가 다르면 이전 신호를 쓰지 않고 모든 종목을 신호 미확인으로 둡니다(경고 문구 표시).
  `_monthly_plan_alloc`에도 계좌 범위를 남깁니다. L3가 이 값을 읽는 방식은 5단계에서 바꿉니다.
- 결과 차이: 같은 계좌 범위에서는 차이가 없습니다. 계좌 선택이나 보유 입력을 바꾼 뒤 분석을 다시 돌리지 않은 경우에만,
  예전에는 이전 범위의 신호로 계획을 냈고 이제는 신호 미확인(계획 미확인, 실행 0)입니다.

## ② 엔진: 명시 비중이 전역 계좌보다 우선
- 바꾼 것: `calc_scores_and_decision`의 `user_curr_w`/`user_targ_w` 기본값을 None으로 두고, 호출자가 비중을 넘기면
  전역 `holdings_table` 행보다 그 값을 씁니다(`get_effective_weights`).
- 결과 차이: 앱 화면은 비중을 넘기지 않으므로 운영 판정은 그대로입니다(선택 계좌 행을 읽음).
  비중을 명시하는 재생·테스트에서만 달라집니다. 테스트 환경의 샘플 계좌에 있는 QQQM 두 사례가 샘플 행(22.4%/22.0%, 비중 초과) 대신
  넘긴 비중을 쓰게 되어 `HARD_BLOCK_OVERWEIGHT`→`CORE_STORM_DCA`, `NEW_ETF_TARGET_FILLED`→`CORE_NEUTRAL_DCA`로 바뀌었습니다.
  새 기준은 `tests/golden/c6_step2_explicit_weight_snapshots.json`. 재생 차이는 아래 '재생 비교'.
- 남은 것: 버킷(`get_effective_bucket`)은 여전히 전역 계좌 행을 먼저 읽습니다. 4단계 재생에서는 샘플 계좌를 비우고 돌립니다.

## ③ 신호 미확인: 추정 폐지
- 바꾼 것: 신호가 없거나(빈 값, `-`) 계산 실패인 종목은 예전처럼 코어 1.0배·레버리지 0.5배(하락 시 단계 배율)로 추정하지 않습니다.
  배율 0, 계획 금액 미확인(L3로 넘기는 값은 NaN = 미확인), 오늘 실행 0, 상태 `❔ 신호 미확인`.
  미확인 종목의 기본 배분은 다른 종목에 재분배하지 않습니다(재분배는 신호가 있는 종목끼리만).
  확정 계획 보존은 3단계(저장)에서 붙입니다. 지금은 세션 계산뿐이라 보존할 확정 계획이 없습니다.
- 결과 차이: 모든 종목에 신호가 있으면 차이가 없습니다(테스트로 고정).
  분석을 아직 돌리지 않아 신호가 비어 있으면 예전에는 코어 100%·레버리지 50% 계획이 나왔고, 이제는 전 종목 미확인입니다.
  특정 종목만 계산 실패면 그 종목만 미확인이고, 나머지 종목 금액은 '그 종목이 없을 때'와 같습니다.

## ④ 항상투자: 안전 차단 우선
- 바꾼 것: 항상투자로 지정해도 엔진 원판정 코드가 아래면 1.0배로 덮지 않고 엔진 배율을 그대로 씁니다.
  하드차단(`HARD_BLOCK_FINANCIAL_F`, `HARD_BLOCK_MACRO_STORM`), 목표 0(`TARGET_ZERO_NO_ADD`, `LEVERAGED_TARGET_ZERO_DCA_EXCLUDED`),
  비중 초과·충족(`HARD_BLOCK_OVERWEIGHT`, `HARD_BLOCK_TARGET_FILLED`, `TARGET_FILLED_HOLD`, `TARGET_FILLED_S_GRADE_WAIT`,
  `BELOW_COST_TARGET_FILLED`, `NEW_ETF_TARGET_FILLED`, `LEVERAGED_TARGET_FILLED_DCA_EXCLUDED`), 데이터확인(`DATA_ERROR`,
  `DATA_UNAVAILABLE`, `LIVE_ONLY_DATA`). 신호 미확인 종목도 항상투자로 덮지 않습니다.
- 결과 차이: 위 코드가 아닌 종목(타이밍 대기·과열 등)은 예전처럼 1.0배입니다. 레버리지는 원래 항상투자 대상이 아니어서 그대로입니다.
  목표비중 0 종목은 원래 계산기 대상에서 빠져 있어 차이가 없습니다.
