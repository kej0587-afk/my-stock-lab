# 일·주·월 차트의 240일선·1000일선 (2026-11-27, 우선순위 2번)

## 확인한 문제 (main `3619f96` 코드)
- 정밀관측소 통합 차트의 일봉 프레임은 `load_precision_price_history(tkr, "1y")`(약 250거래일)이고 이동평균을
  그 프레임으로만 계산했다 → 240일선은 끝부분 몇 봉, **1000일선은 이력이 충분해도 항상 '데이터 부족'**.
- 주·월봉에서 같은 설정 `240`은 240주·240개월 이동평균이었고 범례는 단위 없이 `MA240`.
  주봉 260봉·월봉 180봉으로 잘라 1000주/1000개월은 항상 불가.

## 수정
- 주·월봉을 만든 같은 장기 일봉(10y→max→5y→2y, 캐시 로더 재사용)으로 **N거래일 단순이동평균을 먼저 계산**하고
  각 봉에 대응: 일봉은 그 날짜, 주·월봉은 묶음 날짜 이전 마지막 거래일 값. 진행 중인 주·월은 마지막 일봉 날짜까지.
  일봉 차트는 자기 마지막 봉(현재가 보정 포함)을 같은 날짜 장기 값보다 우선한다.
- 범례: 일봉 `240일선`, 주·월봉 `일봉 240일선`(점선). 주·월봉에서 `봉 단위(N주선·N개월선)`를 고르면 `240주선`처럼 단위 표기.
- 캡션: 선마다 `마지막 값 · 기준 일봉 날짜 · 첫 유효일 · 확보 거래일`, 불가하면 `확보 n거래일 < 필요 N거래일`.
- 투자판정·실행계획·MTF 판정 함수(`build_precision_multi_timeframe_pack`, 고정 계약)는 그대로. 표시 전용.

## 검증
- 새 테스트 `tests/test_chart_daily_basis_ma.py` 5개: 주·월봉 각 봉 값 = 그 봉 마지막 거래일까지 일봉 N개 평균,
  1년 일봉 프레임에서도 1000일선, 이력 부족 확보/필요 표시, 봉 단위 이름, 일봉 이름.
- 클라우드에서 Yahoo SOXL 10년 일봉(2,513개, 2016-11-28~2026-11-25)으로 일·주·월 각각 240일선 111.5846,
  1000일선 48.0255 = 원본 일봉 최근 240/1000개 종가 평균과 일치(같은 공급처 조정 기준).
- 운영 화면 확인: HANDOFF 참조.
