## 원인 (main `a3e027a` 코드로 확인)
1. **정밀관측소가 비중 0%를 명시 전달.** `calc_scores_and_decision(..., app_mode, 0.0, 0.0, 0.0, ...)`의
   세 0.0은 `user_total_asset / user_curr_w / user_targ_w`. 2026-11-26 C-6 2단계(`0db64175`)부터
   `get_effective_weights`는 *명시 비중이 계좌 보유표보다 우선*이므로, 정밀관측소 판정은 모든 종목을
   목표 0%/현재 0%로 계산했다. 당시 문서의 "앱 화면은 비중을 넘기지 않음"은 정밀관측소에 대해 틀렸다.
   Today 화면은 비중을 넘기지 않아 보유표 행을 그대로 읽는다(영향 없음).
2. **신규진입 표만 보유표로 보완.** `render_entry_execution_plan`은 `buy_amt`가 0이면 보유표의
   목표비중(8%)으로 첫 행을 다시 계산했지만, 레버리지 판독(`build_leveraged_precision_state` /
   `build_leveraged_dca_timing_state`)에는 원래 입력(0%)을 넘겼다 → 같은 표에 8%와 `미설정`.
3. **회복 1/6과 미확인은 같은 산식.** 두 값 모두 `build_leveraged_precision_state`의 6항목
   (MA20·MA50·MA120·MACD·RS 기울기·기초축 1W). 보유 중이면 L3 판독의 마지막 봉도 이 값을 쓴다.
   미보유면 `build_leveraged_l3_read`가 `{}`를 돌려 정책 표가 시세로 확인 가능한 값까지 `미확인`으로 냈다.
