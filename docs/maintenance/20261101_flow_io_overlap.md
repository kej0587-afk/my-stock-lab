# 돈흐름 원자료 조회 대기시간 개선

## 범위

기준 커밋 `e0cb0462`의 ETF·테마 수집 순서를 개선했다. 기능, 종목 목록,
점수 산식, 판정 임계값, 문구, 시장방어, 인증·사용자 자료는 바꾸지 않았다.

## 확인과 변경

- ETF 105개·테마 381개 고유 티커 사이에는 중복이 없었다. 무조건적인 실행당
  메모 추가는 하지 않았다. 국내 일봉 캐시와 해외 일괄조회 캐시도 이미 있다.
- 기존에는 해외 다운로드가 끝나야 국내 일봉 작업을 시작했다. 같은 국내 작업을
  먼저 제출하고, 호출 스레드에서 기존 해외 일괄조회를 수행하도록 바꿨다.
- 국내 동시 요청은 프로세스 전체 4개 한도를 유지한다. 해외 다운로드의 기존
  잠금·동시성·타임아웃과 외국/Alpha Vantage 폴백 순서는 유지한다.
- 점수 계산·표 구성·화면 갱신은 호출 스레드에 남는다. 기존 국내 작업 풀을
  사용하며 UI 실행용 작업 스레드나 Streamlit 실행 컨텍스트 공유는 추가하지 않았다.
- 다운로드 실패 시에도 제출된 작업을 종료까지 회수한다. 실패 메타데이터와
  정상/실패 캐시 TTL은 유지한다. 캐시 적중 시 선행 조회를 강제로 하지 않는다.

## 실제 측정

2026-11-01 로컬 공개 시세 조회. 같은 유니버스로 ETF/테마 표를 계산했다.
시작 전 결과 캐시가 없는 별도 프로세스를 썼으며, 유니버스 구성·로그인·화면
렌더링은 측정 구간 밖이다. 기존 전체 화면 21.7초와는 범위가 다르다.

| 단계 | 수정 전 | 수정 후 |
| --- | ---: | ---: |
| ETF 표 | 6.714초 | 3.705초 |
| 테마 표 | 14.020초 | 12.304초 |
| 합계 벽시간 | 20.735초 | 16.010초 |

관측된 감소는 4.725초(22.8%)다. 각 한 번의 실조회이므로 통신 속도 차이를
포함할 수 있으며 Streamlit Cloud 전체 로딩이 22.8% 줄었다는 뜻은 아니다.
ETF 109행·테마 475행의 순서·열·수치·결측·속성이 정확히 같았다.

두 버전 모두 해외 일괄조회 함수 2회, 가격 프레임 경로 486개다. 이는
일괄조회 내부 HTTP 요청이 2개라는 뜻이 아니다. 조회량을 늘리지 않고
독립된 국내/해외 대기시간을 겹치는 변경이다.

공개 원자료·프로파일은 무시 대상 `cache/flow_io_overlap_20261101_*`에
저장했다. 재생 측정은 아래 도구로 같은 입력·기록된 대기시간을 사용한다.

원자료와 기록된 대기시간(배율 1.0)을 고정한 3회 교대 재생의 중앙값은
수정 전 20.827초, 수정 후 18.455초였다. 2.372초(11.4%) 감소했으며
매번 두 표의 값·정렬·결측·속성이 정확히 같았다. 함수 호출량도 동일했다.
실제 API를 다시 호출한 측정은 아니고, Cloud 로딩시간을 보장하지 않는다.

```powershell
.venv311/Scripts/python.exe -m tests.benchmark_money_flow_io_overlap
```

검증 항목: 국내 작업 선행 시작, 해외 조회·점수 계산의 호출 스레드 유지,
순위·실패 속성 일치, 작은 유니버스의 무작업풀 경로, 예외 후 작업 회수,
기존 동시 요청 한도, Streamlit 캐시 적중·진행 표시 재생.

집중 테스트 34개 통과, 전체 회귀 4,307개 통과·1개 건너뜀·하위 테스트
18개 통과(207.34초). 컴파일·차이 검사 통과. 독립 읽기 전용 리뷰에서도
추가 수정이 필요한 정확도·동시성·실패 처리 회귀는 발견되지 않았다.

## 한계와 다음 순서

- 이번 변경은 외부조회 최적화이며 전체 앱 리팩토링 완료가 아니다.
- 기존 `SQ` 조회 불가와 다른 가격 누락은 정상값으로 채우지 않았다.
  티커 변경·원자료 보완은 별도 정확도 작업에서 확인할 대상이다.
- 큰 함수 분리는 이후에도 이전 출력·UI 상태를 고정한 뒤 한 함수씩 진행한다.
- 공식 EPS·과거 매출 컨센서스 대조는 별도 다음 단계다.
