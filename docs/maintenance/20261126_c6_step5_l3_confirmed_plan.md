# C-6/C-11 5단계: L3가 확정 월계획의 남은 잔액을 사용 (2026-11-26)

사용자 결정 7항과 12:59 KST 승인 4항. L3 규칙(예산, 회차, 20거래일 간격, latch)은 바꾸지 않았습니다.

## 바뀐 점
- 전에는 L3가 `_monthly_plan_alloc`(이번 세션에서 월 적립 계산기를 열었을 때만 생기는 값)을 읽었습니다.
- 이제 `app.current_month_monthly_plan_krw`가 Supabase `monthly_dca_plans` / `monthly_dca_executions`에서
  같은 계좌 범위(선택 계좌 집합)·같은 KST 월의 최신 확정 계획을 읽고, 계획 − 집행을 돌려줍니다
  (`monthly_execution.confirmed_plan_remaining`).
  - 확정 계획이 없거나 저장소를 못 읽으면 None → L3는 후보로 남고 사유는 "이번 달 확정 월적립 계획 없음·미확인".
  - 확정된 달에 그 종목 계획이 없으면 0.
  - 집행이 계획보다 많아도 0 아래로 내려가지 않습니다.
- L3 회차 금액 공식은 그대로입니다: min(예산/3, 예산 − 투입액, 목표비중 부족분 − 이번 달 남은 월계획).
  매수 후 보유가 갱신되면 부족분이 줄고, 집행 기록이 남은 월계획을 줄이므로 같은 부족분을 두 번 빼지 않습니다.
- 읽기는 20초 캐시이고, 계획 확정·집행 기록 직후에는 캐시 키(`_monthly_store_rev`)가 바뀌어 바로 새로 읽습니다.
  화면 조회·새로고침은 아무것도 기록하지 않습니다.
- 계좌 범위: 확정 계획은 선택 계좌 집합 기준이고 L3 예산 기록은 기존대로 account_mode `total`입니다.
  L3는 현재 화면의 계좌 선택과 같은 범위의 확정 계획만 읽습니다.

## 테스트

  0 하한, L3 회차 공식 동일.
