# 한국 공시 실제 실적 표가 이유 없이 빠지는 문제 (2026-11-27)

## 발견

PR #100 운영 확인(회사 PC, 12:36 KST 보고서)에서 '**한국 공시 실제 실적 · 발표일과 별도**' 표(15개사)가 '다가오는 일정'과
'시장 스토리'에서 통째로 빠졌다. 12:07본에도 없었고 12:18본에는 있었다. 화면에는 빠진 이유가 전혀 없었다.

## 원인 (코드 경로)

- 표는 `report_dart_earnings.filing_actual_lines`가 `pipeline["packets"]` 중 `financial_values`가 있는 DART 정기보고서 패킷으로 만든다.
- 패킷은 `earnings_filing_sources`의 기업별 수집(`collect`)이 정기보고서 목록·재무제표를 받아야 생긴다. 24초 공식 수집 한도
  (`collection_time_budget`), DART 식별자·목록 오류, 재무제표 미연결이면 그 기업은 이벤트가 없거나 수치가 없다.
- 모든 한국 기업이 이렇게 빠지면 함수가 `[]`를 돌려 표 제목까지 사라졌다. 사유는 `pipeline["coverage"]["missing"]`에 이미 있었지만 쓰지 않았다.
- 12:07·12:36에 어느 사유였는지는 운영 보고서의 진단으로 확인해야 한다(추정: 재부팅 직후 첫 보고서의 한국 수집 시간 한도.
  SEC 8/s 비교 때도 시간 한도 실패 8~10건이 모두 한국이었다). 이번 수정으로 다음 보고서에 사유가 그대로 나온다.

## 수정

`filing_gap_line(pipeline)` 추가. 한국 공시 실제치를 다음으로 구분해 한 줄로 쓴다(사유·개수는 파이프라인 값 그대로, 추정 없음):

| 상태 | 조건 | 예 |
| --- | --- | --- |
| 미계산 | 오늘 점검 전이라 대상 기업이 없음 | `한국 공시 실제치: 오늘 점검 미계산 · 대상 기업 미정(…)` |
| 일부 조회 실패 | 사유에 한도·실패·시간초과·HTTP·오류·제한 | `… 일부 조회 실패 2개 — 공식 공시 수집 시간 한도·이번 조회 보류 2개` |
| 공식값 없음·미연결 | 정기보고서 없음·기준기간 미확인·식별자 미등록, 정기보고서는 찾았지만 재무 수치 미수집 | `… 공식값 없음·미연결 1개 — 조회 기간 내 DART 정기보고서 없음 1개` |
| 확인 결과 0개 | 대상은 있었고 실패·누락 없이 실제치 0개 | `한국 공시 실제치: 확인 결과 0개(…)` |

- 표가 비면 제목 + 이 줄을 보여 준다. 표가 있고 일부만 빠졌으면 표 아래에 같은 줄을 붙인다.
- 한국 기업이 대상에 없고(미국만) 오늘 점검이 끝난 경우에는 아무것도 쓰지 않는다(이전과 같음).
- 수치·판정·수집 범위·한도는 바꾸지 않았다.
