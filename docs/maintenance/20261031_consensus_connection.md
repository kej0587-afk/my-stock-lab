# 밸류·최종체크의 컨센서스 연결

## 확인한 문제

오늘점검은 공통 애널리스트 스냅샷을 사용했지만 밸류와 최종체크는 별도 Yahoo
정보의 목표가를 우선 사용했다. 공통 조회가 실패/지연돼도 별도 응답의 목표가가
남아 있어 서로 다른 목표가와 조회 상태가 표시될 수 있었다. 보완 과정은
캐시가 반환한 원 자료 딕셔너리도 수정할 수 있었다.

밸류의 직접 `get_info` 호출은 공통 메타데이터 캐시와 Yahoo 전역 429
쿨다운을 우회했다. 이미 조회한 정보가 다시 호출되거나 제한 중 요청이
계속되는 별도 경로였다.

## 적용

- `valuation_inputs.resolve_valuation_inputs`는 새 조회 없이 공통 오늘점검
  보강 함수로 평균/중앙 목표가, 참여수, 가격 기준, 출처와 상태를 선택한다.
- 밸류 원자료의 목표가·참여수·투자의견을 제거한 복사본에 검증된 공통
  목표가만 연결한다. 다른 공급자의 인원수나 최고/최저 목표가를 섞지 않는다.
- 평균이 없으면 공통 함수의 중앙값 선택을 유지한다. 원 목표가 종류와
  공급자 기준일은 컨텍스트와 검토 ZIP에 보존한다.
- 화면 현재가가 없으면 공통 조회가 선택한 기준 가격까지 계산에 전달한다.
  다른 밸류 응답의 가격으로 다시 바꾸거나 업사이드를 누락하지 않는다.
- 운영 대조에서 점검의 표시용 $281.48과 밸류의 원시 가격 $281.481이
  분모로 달리 사용됨을 확인했다. 표시 형식은 그대로 두고 원시 가격을
  별도 보존해 업사이드 계산 분모를 통일한다. 파생 점검 캐시만 갱신한다.
- 실패·낡음·차단 상태의 목표가는 원자료에 양수가 남아 있어도 승격하지 않는다.
- 공통 Yahoo `info` 캐시/회로차단기를 사용한다. Yahoo 장애 때 기존 FMP,
  네이버, 키움 보완 경로를 유지하고 부분 성공과 Yahoo 오류를 구분한다.
- 제한 중 부분 성공을 6시간 정상 캐시로 고정하지 않는다. 공통 메타데이터의
  원 조회시각으로 만료를 확인해 외부 캐시가 나이를 다시 6시간 연장하지 않는다.
- 밸류 패널에 목표가·현재가 대비·출처·공급자 기준일·조회시각·상태 표를 표시한다.
  공급자가 기준일을 주지 않으면 `미제공`이며 조회 날짜로 바꾸지 않는다.

점수식, 매매 임계값, 기존 판정문구, 수동/저장 재무점수는 변경하지 않았다.
목표가 입력이 바로잡히면 그 입력을 사용하는 밸류 해석은 달라질 수 있다.
주가 목표가와 분기 EPS/매출 예상치, 회사 가이던스는 별개다. 이번 수정이
실적 예상치 API나 새 공시 대조를 추가한 것은 아니다.

## 근거·검증

- 공식 API 구분: https://ranaroussi.github.io/yfinance/reference/yfinance.analysis.html
- 평균/중앙 선택, 서로 다른 응답의 목표가·참여수, 실패/오래된 자료,
  원본 불변과 수동 0점 보존, 화면/최종체크/오늘점검 업사이드 일치 검사.
- 밸류와 애널리스트의 `info` 실제 공급자 호출 1회 공유, 429 중 추가
  Yahoo 요청 차단 및 FMP 보완 유지, 원 조회시각 만료 검사.
- 관련 회귀 196개 통과(30.89초). 전체 기동/분석 소요시간의 개선율은 측정하지 않았다.
- 기준 가격 전달 보완 후 관련 검사 184개 통과(26.58초).
  독립 리뷰의 현재가 누락/충돌 재현 사례에서도 동일 업사이드를 재확인했다.
- 최종 전체 회귀 4,186개 통과, 1개 건너뜀, 하위 테스트 18개 통과(193.87초).
- 운영에서 발견한 표시 반올림 분모 차이 보완 후 전체 회귀 4,188개 통과,
  1개 건너뜀, 하위 테스트 18개 통과(193.22초).

남은 별도 과제는 실제 분기 EPS·매출 예상치를 같은 보고기간의 실적과
대조하고, 최신 공시가 저장 재무에 반영됐는지 공식 발표와 확인하는 것이다.
