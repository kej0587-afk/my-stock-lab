# 마지막 완성본 먼저 표시 (2026-11-27)

사용자 요청(02:06 KST): "새 시황 생성에 시간이 걸리더라도 마지막 완성본이 있으면 기준 시각과 함께 먼저 읽을 수 있게 하고,
새 보고서가 완성되면 교체."

## 이전 동작
- 시황 본문은 세션 메모리(`today_market_memo_text`)에만 있었다. 같은 세션에서는 생성 중에도 이전 본문이 화면 위쪽에 남지만,
  새 탭·재접속·재부팅이면 빈 화면에서 시작해 버튼 클릭 후 약 2분을 기다려야 첫 본문을 읽을 수 있었다.
- 배포(코드 변경) 뒤에는 `invalidate_saved_report`가 이전 자동 뉴스픽을 비웠다.

## 변경 (`stock_lab_core/report_latest.py`, `app.py` 시황 보기 호출부)
- 새 리포트가 완성되면 로그인 계정 + 선택한 계좌 묶음별로 한 번 저장한다. 완성본은 ‘## 기준일’이 있는 자동 뉴스픽이고
  `오늘 점검 미계산` 표시가 없어야 한다. 붙여넣은 메모, 안전 안내 초안, 미계산 리포트는 저장하지 않는다.
  - Supabase `report_latest`(계정·계좌 묶음당 1행, `docs/20261127_report_latest.sql`).
  - 로컬 사본 `cache/market_report_latest_<계정+계좌 해시>.json`(Git 제외).
- 범위 보장(사용자 확인 요청 2026-11-27 06:28 KST):
  - SQL: RLS 강제(force), anon·authenticated는 모든 동작 거부(restrictive), 서버 전용 service_role에만 select·insert·update.
    기본키 (owner_email, account_key). account_key는 계좌 이름 없이 선택 계좌 묶음의 해시(`acc_` + 32자)만 담는다.
  - 앱: 소유자는 로그인 검증된 `CURRENT_USER_EMAIL`만 쓴다(공개 데모는 저장·조회 안 함). 읽기는 owner_email과 account_key로
    거르고, 돌아온 행의 두 값을 다시 확인한다. 쓰기는 두 값을 키로 upsert하고, 돌아온 행이 같은 소유자·묶음일 때만 성공으로 본다.
  - 같은 세션에서 계좌 필터를 바꾸면 그 묶음의 완성본을 다시 찾는다. 없으면 이전 묶음의 리포트에 ‘마지막 완성본’ 표시를 붙이지 않는다.
- 생성 실패(안전 안내 초안)나 미계산 리포트가 나오면 화면을 기존 완성본으로 되돌리고 이유를 경고로 보여 준다. 다음 완성본이 나오면 교체한다.
  이전 완성본이 없으면 새 리포트를 그대로 보여 주되 저장하지 않는다.
- Today 계산 전에도 보이게 했다. 브리핑 보기가 ‘시황’이 아니면 "마지막 시황 완성본: 시각 · ‘시황’ 보기에서 바로 읽을 수 있습니다" 한 줄을 띄운다.
- 시황 칸이 비어 있으면 세션당 한 번 마지막 완성본을 불러와 먼저 보여 주고, 위에 안내를 띄운다:
  "마지막 완성본을 먼저 표시합니다(YYYY-MM-DD HH:MM KST 생성 · 현재 시세와 별도). … 새 시황을 만들면 완성되는 즉시 교체".
- 불러온 사본은 현재 코드 버전으로 표시해 배포 직후에도 지워지지 않는다(안내문이 이전 리포트임을 알린다).
- 리포트 내용, 판정, 점수, `render_today_market_memo_panel`(시험으로 고정된 함수)은 바꾸지 않았다.
