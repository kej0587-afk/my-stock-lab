# 마지막 완성본 먼저 표시 (2026-11-27)

사용자 요청(02:06 KST): "새 시황 생성에 시간이 걸리더라도 마지막 완성본이 있으면 기준 시각과 함께 먼저 읽을 수 있게 하고,
새 보고서가 완성되면 교체."

## 이전 동작
- 시황 본문은 세션 메모리(`today_market_memo_text`)에만 있었다. 같은 세션에서는 생성 중에도 이전 본문이 화면 위쪽에 남지만,
  새 탭·재접속·재부팅이면 빈 화면에서 시작해 버튼 클릭 후 약 2분을 기다려야 첫 본문을 읽을 수 있었다.
- 배포(코드 변경) 뒤에는 `invalidate_saved_report`가 이전 자동 뉴스픽을 비웠다.

## 변경 (`stock_lab_core/report_latest.py`, `app.py` 시황 보기 호출부)
- 새 리포트가 완성되면(‘## 기준일’이 있는 자동 뉴스픽만, 붙여넣은 메모·안전 안내 초안은 제외) 계정별로 한 번 저장한다.
  - Supabase `report_latest`(계정당 1행, `docs/20261127_report_latest.sql`, 서버 전용·계정 고정, report_history와 같은 방식).
  - 계정 해시 이름의 로컬 사본 `cache/market_report_latest_<sha>.json`(Git 제외).
- 세션의 시황 칸이 비어 있으면 세션당 한 번 마지막 완성본을 불러와 먼저 보여 주고, 위에 안내를 띄운다:
  "마지막 완성본을 먼저 표시합니다(YYYY-MM-DD HH:MM KST 생성 · 현재 시세와 별도). … 새 시황을 만들면 완성되는 즉시 교체".
- 불러온 사본은 현재 코드 버전으로 표시해 배포 직후에도 지워지지 않는다(안내문이 이전 리포트임을 알린다).
- 리포트 내용, 판정, 점수, `render_today_market_memo_panel`(시험으로 고정된 함수)은 바꾸지 않았다.

## 테이블이 없을 때
- `schema_unavailable`로 기록하고 로컬 사본만 쓴다. 같은 서버의 새 세션에는 보이지만 재부팅하면 사라진다.
- 재부팅 뒤에도 보이려면 위 SQL을 Supabase SQL 편집기에서 한 번 실행해야 한다(새 테이블 추가만, 기존 테이블·행 변경 없음).

## 운영 확인
- 미확인. 확인 방법: SQL 적용 → 리포트 1회 생성 → 앱 재부팅 → 시황 보기에서 안내문과 생성 시각이 바로 보이는지, 새로 생성하면
  안내문이 사라지고 새 본문으로 바뀌는지 확인한다. 결과를 이 문서와 HANDOFF에 KST 시각으로 기록한다.
