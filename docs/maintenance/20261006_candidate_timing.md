# 후보 품질과 진입조건 정리

## 확인한 기준

- 입력: `stock_lab_review_export_20261006_0141`의 고유 종목 79행.
- PANW는 `타점 탐색 중`, `눌림/종가 확인`인데 게이트가 실행가능이었다.
- 섹터RS 결측은 31행이며 개별주 25개와 ETF/혼합자산 6개였다.
- 애널목표Upside는 ETF 22개를 포함해 79행 모두 비어 있었다. 기존 내보내기에 조회 오류가 기록되지 않아 당시의 조회 실패 원인을 단정할 수 없다.

## 반영한 구조

`stock_lab_core/decision_workflow.py`가 후보 품질, 기존 표시 판정, 실행 게이트와 배타적인 탭 분류를 연결한다. 오늘점검, 전광판 요약과 정밀관측소가 이 공통 계산을 사용한다.

`후보품질`과 `후보점수`는 기존 후보 평가의 원래 값이다. 기존 `📌후보등급`, `🔥기술적 타점`, `최종읽기`의 문구 정의는 유지한다. 타점 탐색, 회복관찰, 눌림/종가 확인은 대기이며 후보 등급만으로 실행을 승인하지 않는다. 주봉/월봉 추세훼손과 지역별 레버리지 시장방어도 게이트에 반영한다.

애널 목표가는 차트 R/R의 목표와 다른 자료다. 음수 애널 업사이드와 약한 섹터RS는 `후보검토사항`에 표시하고 별도의 시간조건으로 취급하지 않는다. R/R 미산출은 데이터확인, R/R 1 미만과 투영상단은 대기로 유지한다. 실행 후보 수를 늘리기 위한 점수나 기준값 변경은 없다.

정밀관측소의 매수 전 최종 체크와 차트 실행 체크표가 공통 게이트를 따르며, 개별 차트 조건 통과가 종합 대기를 우회하지 않는다. 실제 가격이나 자료 시점이 다르면 결과는 달라질 수 있다.

## 외부자료

`stock_lab_core/today_enrichment.py`는 표에 표시한 현재가를 먼저 사용하고, 가격이 없으면 제공처 가격과 가격 조회를 순서대로 시도한다. 목표가, 평균/중앙값 구분, 참여수, 제공처, 목표가 기준일, 실제 조회시각과 결측사유를 보존한다. 중복 종목을 같은 조회에서 반복 요청하지 않는다.

미국 목표가는 Yahoo financialData와 yfinance 제공 API를 사용한다. [yfinance 공식 문서](https://ranaroussi.github.io/yfinance/reference/yfinance.analysis.html)의 목표가 API는 `current`, `low`, `high`, `mean`, `median` 필드를 제공한다. 국내 종목은 공개 FnGuide 컨센서스로 보완한다. 최고/최저 목표나 차트 투영값을 평균 목표가로 대체하지 않는다. 제공처에 기준일이 없으면 기준일을 새로 만들어 넣지 않는다.

로컬 Windows의 한글 가상환경 경로에서 yfinance의 `curl (77)` 인증서 파일 오류를 재현했다. `stock_lab_core/yahoo_transport.py`가 원래 신뢰 인증서 묶음을 ASCII 임시 경로로 복사하고, yfinance가 지원하는 검증 세션으로 전달한다. 인증서 검증을 끄지 않고 설치된 라이브러리나 운영체제 설정을 수정하지 않는다. 사용자 지정 CA가 있으면 그대로 보존한다.

`sector_map.json`에 누락 개별주 25개를 추가했다. 기업/거래소와 운용사 공식 자료에 근거한 31건의 출처, 확인일과 대체지수 한계는 `stock_lab_core/data/sector_benchmark_sources.json`에 기록했다. 광역지수 3개, TDF, 전력 테마 ETF의 자기비교와 실물 구리는 각각 제외 사유를 가진다.

`stock_lab_core/relative_strength.py`는 종목과 벤치의 같은 거래일을 맞춰 RS를 계산한다. 가격없음, 이력부족, 기준일차이를 중립값으로 숨기지 않는다. 신규 분류는 업종의 대체 비교이며 동종기업만으로 구성된 정밀 지수라고 가정하지 않는다.

## 갱신과 검증

오늘점검의 수동 새로고침에서 목표가 캐시도 갱신한다. 돈흐름 원자료 갱신 후 후보 목록 캐시를 재사용하지 않으며, 재계산하지 않은 이전 결과에 새 입력 서명을 붙이지 않는다. 판정 버전을 변경해 이전 디스크 스냅샷과 구분한다.

검증 범위는 후보/타점 분리, PANW 대기, 낮거나 없는 R/R, MTF 방어, 레버리지 시장방어, 차트 우회, 날짜 정렬, 출처 매핑, 목표가 제공처 파싱과 기존 판정 스냅샷이다. 회귀 테스트는 기존 규칙의 동작을 검증하며 투자 성과 백테스트와는 다른 작업이다.

- 전체 회귀 테스트 564개 통과. 기존 pykrx의 deprecation 경고 1개가 남았다.
- 독립 리뷰에서 관련 회귀 189개를 별도로 실행했다. 기존 판정문구 golden 테스트도 통과했다.
- 미국 MSFT/NVDA/AAPL, 국내 000660/005930/267260의 목표가 실조회 6건에서 실제 컨센서스를 확인했다. 국내 목표가 기준일은 제공처의 2026-10-02였다. 전체 관심종목이 모두 목표가를 제공한다는 의미는 아니다.
- 인증서 보완 후 DDOG/IGV의 3개월 가격 이력은 각각 65행으로 조회됐고, 동일 거래일 기준 섹터 RS와 2026-10-05 기준일이 산출됐다.
- 체험모드 초기 화면과 MSFT 정밀 분석을 브라우저에서 확인했다. 후보 A급은 유지하면서 비중 초과 게이트는 방어우선, 최종 체크는 매수 금지였고, 실제 섹터RS/벤치/기준일과 애널 업사이드/출처가 표시됐다. 오늘점검의 전체 돈흐름 초기 계산은 오래 걸려 끝까지 확인하지 못했다. 전체 초기 조회 지연은 별도의 개선 대상이다.
- 후속 독립 리뷰가 찾아낸 실제 정밀 화면의 제거된 변수 참조와 동시 세션 초기화 시 인증서 파일 수명 문제를 수정했다. 제거 변수 참조 회귀와 4개 스레드의 최초 조회/캐시 해제/GC 후 파일 유지 회귀를 추가했다.

앱을 다시 시작한 후 `오늘 종목 점검 계산/새로고침`으로 새 결과를 생성해야 원래 후보 품질과 추가 외부자료가 내보내기에 포함된다.

## 다음 구조 정리

이번 단계에서 실행 흐름, 목표가 보강과 RS 계산을 공통 모듈로 분리했다. 큰 `app.py`에는 화면별 정책 보정과 렌더링이 여전히 남아 있다. 이후 분리는 현재 회귀 테스트를 기준으로 화면 정책 보정, 후보 데이터 수집, 렌더링 순서로 진행할 수 있다.

실제 정밀관측소와 체험모드 정밀관측소의 외부자료/돈흐름/시장 게이트 연결도 `build_precision_execution_workflow()` 하나로 묶었다. 체험모드에도 일봉·주봉·월봉 및 패턴 확인을 적용한다. 인증/저장/DB 구조와 투자 판정문구 정의는 변경하지 않았다.
