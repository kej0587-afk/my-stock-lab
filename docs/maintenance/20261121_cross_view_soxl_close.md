# 화면 간 근거 연결과 SOXL 누락 종가 복구

2026-11-21 KST. 시작 `c895a19b`, 작업 시작 시 main/origin 일치·clean.
화면 간 고정 입력 비교 도중 사용자가 SOXL 42.34 / 정규장 종가 30.88 불일치를
보고해 가격 입력 오류 수정을 우선했다. 가격 수정은 단순 리팩토링이 아니다.

## 1. 화면 간 근거 연결

정밀관측소 `build_precision_execution_workflow`가 이미 계산된 현재/목표 비중을
반환하지 않아 공유 근거 표에서 비중이 미연결됐다. 기존 게이트 계산이 끝난 후
`현재비중`, `목표비중` 두 표시 필드만 전달한다. 누락은 NaN, 실제 0은 0으로 유지.
코드 `1a9989fb`; 비중·점수 재계산이나 매매 기준 변경은 없다.

| 고정 사례 | 이전·새 함수 비교 | 포트폴리오 연결 |
| --- | --- | --- |
| GOOGL | 기존 필드 동일, 비중 표시 2개 추가 | readiness/가격 입력 ID 동일 |
| 379810.KS | 기존 필드 동일, 비중 표시 2개 추가 | readiness/가격 입력 ID 동일 |
| SOXL | 기존 필드 동일, 비중 표시 2개 추가 | readiness/가격 입력 ID 동일 |

저장된 결정값과 고정 어댑터를 재사용한 연결 검증이다. 원래 계좌 전체를 재계산한
운영 비교는 아니다. 실제 저장본의 GOOGL·SOXL은 조회시각과 가격 입력 ID가 다르다.
379810은 같은 가격 ID에서도 오늘점검 `HARD_BLOCK_OVERWEIGHT`, 정밀관측소
`CRISIS_PANIC_SELL_OFF`였다(둘 다 방어우선). 가격 ID는 시장/계좌/자유입력 모드까지
동일하다는 뜻이 아니다. `is_free=True`는 기존 계좌 제한을 건너뛰며 오늘점검은
False지만, 구 ZIP에는 선택 모드가 없어 그 차이가 원인이라고 확정할 수 없다.
이 이유만으로 기존 우선순위나 판정을 강제로 맞추지 않았다.

## 2. SOXL 원자료 오류 재현

- 운영 수정 전 검토 ZIP(10:16 KST)은 현재가 **42.34**, 공급처/시각/세션 미확인.
  원자료 마지막 Close는 **11/19 45.30**, 11/20은 현재가만 넣은 별도 보정 봉이었다.
- Yahoo 공개 chart API와 yf.download 모두 11/20 시가 **42.40**, 고가 **42.57**,
  저가 **29.82**, 거래량 **533,762,471**을 보내면서 **Close만 null/NaN**이었다.
- 같은 응답의 regularMarketPrice는 **30.88**, regularMarketTime은
  **11/20 16:00:04 미국 동부 / 11/21 06:00:04 KST**였다.
  [Yahoo SOXL history](https://finance.yahoo.com/quote/SOXL/history/)도 종가 30.88.
- 기존 정리기는 Close 없는 마지막 행을 제외했다. 종가 대체 함수도 그 행을
  건너뛰어 45.30을 선택했다. 장외 우선 종목의 조회 순서는 시각 없는 KIS daytime
  후보를 chart보다 먼저 시도할 수 있었다. **42.34의 실제 공급처는 구 ZIP에
  기록되지 않아 확정할 수 없다.**

## 3. 수정 범위와 방어 조건

`yahoo_daily_close`는 기존 마지막 일봉의 Close가 비었을 때만 같은 공급사의
정규장 마감 메타데이터를 검증한다. 종목·뉴욕 거래일·거래소 달력의 실제 마감시각,
거래시각(마감 1분 전~15분 후)·현재시각·OHL 가격 범위를 모두 확인한다.
휴장/마감 전/날짜 불일치/미래시각/범위 밖/이미 있는 Close는 보완하지 않는다.
Adj Close는 조정 근거가 없어 그대로 미확인이다. 전날 값을 forward-fill하지 않는다.

단건/일괄 일봉 조회 모두 같은 보완 함수를 사용한다. 정상 완성 봉은 추가 요청 0회,
누락 미국 종가에만 기존 60초 캐시 종가 조회를 사용한다. 가격·이력 TTL은 변경하지
않았다. 장외 우선 종목도 chart/download 후 시각 없는 KIS daytime을 시도하도록
수정했다. 정규장·프리마켓·애프터마켓 순서와 나머지 fallback은 유지한다.

이것은 **잘못된 가격 입력 수정**이다. 점수 산식·임계값·판정 문구는 유지하지만,
수정된 일봉/현재가로 지표·등락·판정 결과가 달라질 수 있다. 이를 동일 입력의
판정 보존이라고 주장하지 않는다. SOXL 가격을 코드에 하드코딩하지 않았다.

10:41 KST 로컬 실조회: 원자료 Close 여전히 null, 복구 일봉 Close **30.88**.
별도 시간외 시세는 **33.3694**, 공급 봉 시각 **09:59:59 KST**, 세션 post.
사용자가 확인한 32.94와 조회시각/공급처가 같다는 증거는 없으므로 32.94를
정규장 종가로 덮어쓰거나 현재값을 고정하지 않는다.

## 검증

- 비중 연결 전 selected decision **1,638 passed / 155.78s**, 이후
  **1,638 passed / 152.667s**. 가격 수정 후 최종 **1,638 passed / 153.218s**,
  `decision_bqkmn9n1`. 실패·오류·skip·소스 변경 없음.
- 추가 읽기 전용 리뷰에서 NaT 공급시각과 중복 Close 열 보호를 보강했다.
  시각 미확인은 종가로 채택하지 않고 중복 열은 기존 cleaner에 그대로 넘긴다.
- 새 누락 종가·원자료 불변성·일괄 연결·대체 순서·비중 연결 포함 관련 최종 **75 passed / 26.26s**.
- selected prices 최종 **646 passed / 60.359s**, `prices_eeb6nivt`.
  첫 실행의 11개 실패는 과거 조회 순서/함수 본문을 고정한 계약이었다.
  승인된 두 조건문과 종가 보완 세 문장만 정확히 되돌리는 AST 비교 및 명시적
  장외 순서 검증으로 갱신했다. 나머지 본문 동일성은 계속 검증하며 golden은 미갱신.
- 테스트는 수익성 검증이나 전체 네트워크/전체 UI 테스트가 아니다.
