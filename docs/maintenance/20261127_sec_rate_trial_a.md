# SEC 요청 초당 8건 시험 (A안, 사용자 결정 2026-11-27 02:06 KST)

## 무엇을 바꿨나
- `stock_lab_core/sec_rate.py`: 이 앱 프로세스의 모든 SEC 요청(www.sec.gov, data.sec.gov, efts.sec.gov)을 `requests.Session.send`에서
  하나의 1초 창으로 묶습니다. 동시 사용자·화면·백그라운드 작업·재시도가 모두 같은 창을 씁니다.
  - 시험(A안): 어느 연속 1초에도 최대 8건. 기존: 최대 5건(예전 0.2초 간격과 같은 속도).
  - 창 안 요청이 8건을 넘는 일이 생기면(구조상 일어나지 않아야 함) 즉시 기존 속도로 복귀(`window_over_8`).
  - SEC가 429 또는 "Request Rate Threshold Exceeded" 403을 보내면 모든 SEC 요청을 `Retry-After`(없으면 600초) 동안 멈춥니다.
    멈춘 동안의 요청은 보내지 않고 `sec_rate_limited` → 시황에 "SEC 접근 제한으로 요청 일시 중지·조회 실패"(일부 조회 실패로 셈).
    재개 뒤 제한이 다시 오면 기존 속도로 복귀(`repeated_access_limit`).
- 실적 공시 수집(`earnings_filing_sources`)의 예전 0.2초 간격은 이 창으로 대체했습니다. 측정 이름 `earnings_discovery.sec_rate_wait`는 유지,
  앱 전체 대기는 `sec_rate_wait`, 카운터 `sec.request`, `sec.mode.trial_8|legacy_5`, `sec.access_limit`, `sec.blocked_by_access_limit`.
- 비교 스위치: Streamlit secrets(또는 환경변수) `sec_rate_mode = "legacy"`이면 그 부팅 동안 기존 속도. 값을 지우면 A안.

## 비교 방법과 채택 기준 (사용자 지시)
- 같은 종목·공시 범위, 같은 24초 조회 한도에서 **재부팅 직후 첫 시황**끼리 기존 속도 ↔ A안 3쌍, 중앙값 비교. 재계산(보관 문서 재사용)은 별도 기록.
- 기록 열: `버튼 클릭 → 첫 요약 표시 시간 | 시황 전체 완료 시간 | SEC 대기 시간·요청 수 | 공식 공시 확인 종목 수 | 시간 한도로 일부 조회 실패한 종목 수`.
- 채택: ① SEC 대기 30% 이상 감소(55초 → 38.5초 이하)이고 시간 한도 실패가 늘지 않음, 또는 ② 시간 한도 실패 30% 이상 감소(24 → 16개 이하)이고
  SEC 대기가 늘지 않음. 어느 경우든 공식 확인 종목 수가 줄지 않아야 함. 미달이면 기존 속도로 복귀하고 실험 종료.
- 7일 안에 3쌍이 모이지 않으면 `표본 부족·효과 미확인`으로 기록하고 기존 속도로 복귀. 40% 단축은 예상치일 뿐입니다.
