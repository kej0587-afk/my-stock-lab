# 모바일 시황 진입 위치

## 관찰

412 x 915 브라우저 viewport, 실제 갤럭시는 아니다.
오늘점검 시황을 선택한 상태에서 시황 버튼 문서 좌표 y=2,568px, 시황 제목 y=2,700px.
보유관리 요약·카운터·종목 실행계획이 선택 화면 앞에 항상 렌더되어 약 3화면을 내려야 했다.
시황 표는 336~370px 안에 있었지만 다열·긴 본문은 여전히 읽기 어려워 별도 후속 대상이다.

## 변경

- 기존 선택기를 브리핑 제목 바로 아래로 이동. 새 선택기/상태 키/중복 차트를 만들지 않았다.
- 시황·뉴스·키움은 선택한 화면을 먼저 렌더. 시장모드와 실행 제한은 짧은 줄로 유지한다.
- 보유관리·시장 화면의 기존 수치/근거/추천·시장판은 유지한다.
- 시황 보존·복원·owner/account 범위와 생성 전후 저장 호출은 그대로 별도 함수로 분리했다.
- 종목 계산/판정/금액 함수는 바꾸지 않았다. 연구 규칙 적용 없음.

## 검증

- 선택 화면, 미계산 경고, 마지막 정상 리포트 보존, 계정 범위, 기존 위젯 상태 관련 43개 통과(12.94초).
- app.py 함수 AST 비교: 기존 변경 함수는 `render_today_unified_briefing_panel` 하나,
  `_render_briefing_report_surface` 추가. `calc_scores_and_decision` 동일.
- 기존 `briefing_render` 시간 측정 decorator는 원래 전체 함수에 유지한다.
- report 회귀 208개 통과(43.378초). 전체 앱 테스트 재통과를 뜻하지 않는다.
- 운영 y 좌표/화면은 배포 후 확인한다. 실기기 첫 표시 시간으로 환산하지 않는다.
