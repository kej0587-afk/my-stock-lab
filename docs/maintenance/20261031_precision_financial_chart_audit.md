# 정밀관측소 재무·차트·화면 연결 점검

## 범위

정밀관측소의 저장 재무점수, 최신 밸류 자료, 일·주·월봉, 전광판·오늘점검·돈흐름 연결을 점검했다. 기존 매매 판정 문구와 등급 임계값은 유지한다. 자료 기간·단위 오류와 실패 처리 수정은 같은 입력에서도 잘못 계산하던 결과를 바꿀 수 있다.

## 중요한 발견

| 우선순위 | 확인한 문제 | 처리 |
| --- | --- | --- |
| 높음 | 운영 GOOGL 검토 파일은 저장 재무의 최신 분기가 2026-03-31인데, 밸류 표에는 더 최근 TTM 자료가 있었다 | 재무 자료기간·계산시각·최신 발표 반영 미확인 상태 표시. 저장 점수는 가격 조회로 갱신되지 않는다고 구분 |
| 높음 | 조회 실패의 임시 점수가 기존 정상 자동점수·원자료를 덮어쓸 수 있었다 | 실패하면 기존 저장 점수와 수동점수 보존. 실패를 저장 완료로 표시하지 않음 |
| 높음 | 재무 재계산 뒤 전광판·오늘점검은 이전 계산을 계속 표시할 수 있었다 | 저장 성공 후 계산 캐시 무효화. 저장 근거의 해시도 캐시 키에 포함해 점수가 같아도 분기 변경 감지 |
| 높음 | FMP의 동반 재무표를 찾지 못하면 같은 연도의 다른 분기 또는 첫 행으로 대체 | 실제 보고기간을 맞추고 불명확하면 누락으로 처리. 표 간 매칭 실패는 SEC 대체 조회로 전달 |
| 높음 | SEC는 제출 문서의 fy/fp를 실제 보고기간처럼 사용. 누적 현금흐름·Q4·비연속 분기 비교도 문제 | 실제 start/end·단위·계정을 확인. 누적 차감의 근거 보존. 연속 분기만 QoQ 비교 |
| 높음 | 네이버 실적 셀이 비어 있으면 예상치 셀을 대신 사용하고 실제 0은 버림 | 실적 기간의 셀만 사용. 실제 0 보존. 예상치만 있는 표를 확정 실적으로 사용하지 않음 |
| 높음 | 저장된 2% 성장률을 밸류 화면에서 200%로 해석 가능 | 저장 재무의 %p를 API 규약의 소수 비율로 경계에서 정규화 |
| 높음 | 핵심 원자료 미수집이 실적 악화처럼 감점될 수 있음 | 일반기업의 매출·영업이익·순이익·OCF·자본·부채, 금융업의 순이익·자본을 최소 확인. 누락하면 정식 점수 저장을 보류하고 기존 성공값 보존. 실제 0은 유효값 |
| 높음 | 돈흐름 단독 화면은 오늘점검과 달리 시장 가드를 전달받지 않음 | 동일 시장 가드 연결. 공통 실행 제한을 상단에 표시. 원천 흐름 후보 순위는 매수 허가와 구분 |
| 높음 | 주·월봉 조회 실패 후 자료부족인데 실행가능으로 남을 수 있음 | 조회 실패 상태를 전달하고 기존 데이터확인 게이트로 분류 |
| 중간 | 실적 예정일이 지났다는 이유만으로 발표 완료라고 표시 | 시장 현지 날짜로 D-day 계산. 예정일 경과와 실제 발표 확인을 구분 |
| 중간 | 돈흐름 문맥 연결 시 원자료 날짜 컬럼 유실 | 원천 날짜를 보존해 연결·검토 파일에서 확인 가능하게 함 |

GOOGL의 2026-09-30 분기 실적 발표일은 10/28로 공식 공시에서 확인했다. 저장된 Q1 점수는 그 발표를 반영한 점수라고 볼 수 없다. 이는 운영 저장 자료의 사례이며 모든 종목을 실시간 검증했다는 뜻은 아니다. [Alphabet 공식 SEC 실적 공시](https://www.sec.gov/Archives/edgar/data/1652044/000165204426000080/googexhibit991q32026.htm)

## 갱신 계약

| 자료 | 현재 갱신 방식 | 주의점 |
| --- | --- | --- |
| 기업 재무 원자료 | 캐시 6시간, 자동 재무 재계산 시 관련 캐시 갱신 | 원천 API 반영 지연은 별도. 저장된 점수가 6시간마다 자동 재계산되는 구조는 아님 |
| 저장 1~4점 재무점수 | 선택 종목 재계산 또는 일괄 재계산 후 저장 | 실패하면 기존 성공값을 유지하며 성공으로 표시하지 않음. 수동 지정은 계속 우선 |
| 목표가·투자의견 | 관련 스냅샷 캐시. 재무 새로고침에서 같이 무효화 | 애널리스트 목표가는 다음 분기 EPS·매출 컨센서스가 아님 |
| 실제 실적 발표 | 공시/IR 결과와 실제 보고기간으로 확인해야 함 | 예정일 캘린더·뉴스만으로 확정 실적을 채우지 않음 |
| 시세·차트 | 별도 가격 캐시와 현지 거래일 기준 | 현재가 갱신만으로 저장 재무가 최신 발표를 반영했다고 표시하지 않음 |

SEC companyfacts는 공시 중 계속 갱신되지만, 이것이 제3자 공급 API나 앱의 저장점수가 즉시 갱신된다는 보장은 아니다. API 자료의 회계 기간과 단위를 확인해야 한다. [SEC API 안내](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)

## 남은 설계 판단

| 항목 | 현행과 문제 | 권장 방향 |
| --- | --- | --- |
| 후보 품질 | 재무와 기술을 합한 점수라 순수 기업 품질이 아님 | 기업 품질, 기술 타점, 계좌 실행 제한의 세 축을 명시적으로 분리 |
| 재무 근거 중복 | 분기 매출/이익 증가와 모멘텀은 같은 수치. OCF 관련 여러 항목도 같은 원자료 | 경제적 근거별 ID로 묶고 중복 가중치를 확인. 단순 삭제 대신 45/25/5 등급 경계와 함께 병행 검증 |
| 최종 체크 중복 | 시스템 타점의 종합 차단과 개별 MTF 차단이 같은 위험을 두 번 세기도 함 | 종합 상태는 요약, 개별 사유는 근거로 두고 독립 위험 개수로 집계할지 결정. 이번에는 기존 최종 문구·차단 개수 임계값 유지 |
| 결측 통과 | 일부 상세 체크는 지표가 NaN이어도 과열 없음/매크로 통과로 표시 | 미확인과 통과를 구분하는 상세 체크 상태 및 집계 규칙 재설계 필요 |
| 돈흐름 신선도 | 날짜는 보존했지만 모든 원천의 동일 거래일·만료 정책이 통일되지 않음 | 원천별 가격 기준일과 사용 가능 기간을 계약으로 정하고 오래된 문맥의 실행 영향 제한 |
| 전체 컨센서스 | 목표가와 다음 분기 EPS·매출 예상치는 서로 다름. 모든 종목의 동일 분기 컨센서스는 미연결 | 같은 분기·통화·GAAP/조정 기준을 확인할 수 있는 공급원부터 연결. 미연결 값을 목표가로 대체하지 않음 |
| SEC 비교 한계 | 같은 계정·단위·기간이어도 제출본 간 재작성/연결범위 변화를 companyfacts만으로 완전히 증명 불가 | 차감 provenance 보존. 중요한 판단은 원 공시 확인. IFRS/20-F·전환 회계연도는 범위 밖 |

후보품질과 타점·게이트의 결론이 다르다는 사실만으로 오류는 아니다. **좋은 기업 / 지금 진입 조건 / 계좌의 실행 허용**은 서로 다른 질문이다. 다만 최종 체크가 같은 근거를 중복 세는 것은 별개의 설계 문제다. 차트 위 0~100 성적표는 기존 1~4점·후보등급·매매판정에 합산되지 않는다.

사용자의 최종 결정을 대신하도록 매수금지를 임의 완화하지 않았다. 백테스트 없이 점수 임계값의 투자 성과를 보증할 수 없으며, 다음 설계 단계는 새 점수를 즉시 적용하는 것이 아니라 기존/중복 제거 대안을 같은 입력에서 병렬 비교하는 것이다.

## 검증 기록

합성 데이터의 확정값/예상치 구분, 실제 0, 저성장 퍼센트 단위, 실패 저장, 캐시 연결, 보고기간 일치, SEC 누적/Q4, 날짜 정렬, 결측 거래량, 추세선 좌표를 검증했다. 대표 판정의 기존 출력 검증도 유지한다. 전체 회귀 **3,701개 통과, 12개 건너뜀, 하위 테스트 18개 통과(162.66초)**. 차트 범례를 아래로 옮긴 뒤 관련 **27개 추가 통과**. 구문 검사·diff 공백 검사 통과.

운영 앱에서 오늘점검·전광판·돈흐름·정밀관측소 및 GOOGL 일/주/월봉을 열어 점검했다. 개인 검토 ZIP에서 저장 Q1과 최신 자료의 기간 차이를 확인했다. 수정본의 로컬 체험모드에서는 QQQM과 MSFT를 조회해 성적표·벤치마크 RS·차트 표시와 데이터 누락 표시를 확인했다. 체험모드 자료는 운영 계좌의 실제 점수·잔고 검증을 대신하지 않는다. 새 95종목 전체 성능 측정이나 모든 종목의 최신 공시 전수 검증은 이번에 수행하지 않았다. 계좌 자료·인증 정보·개인 검토 ZIP은 저장소에 포함하지 않는다.
