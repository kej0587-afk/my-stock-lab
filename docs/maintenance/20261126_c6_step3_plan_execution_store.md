# C-6/C-11 3단계: 계획 · 집행 · 오늘 실행가능 분리 + Supabase 저장 (2026-11-26)

사용자 결정(2026-11-26 09:14 KST) 1·6·7항. 월적립 배율표, 판정 엔진, Today 게이트, L3 규칙은 바꾸지 않았습니다.
L3가 확정 계획을 읽는 연결은 5단계입니다.

## 화면 (월 적립 리밸런싱 계산기 아래 새 표)
| 열 | 뜻 |
|---|---|
| ① 계획 | 같은 계좌 범위·같은 KST 월의 확정 계획(최신 버전). 없으면 공통 계산의 임시 계획. 신호 미확인이면 미확인 |
| ② 집행 | 이번 달 집행 기록 합계(같은 계좌 범위). 저장소를 못 읽으면 미확인 |
| ③ 오늘 실행가능 | ①−②, 목표비중 부족분, 월적립 게이트, 1차 정찰 1/3, 가용 현금 중 가장 작은 값 |
| ④ 남은 대기 | ①−②−③ |

- ③을 표시해도 ②는 늘지 않습니다. ②는 '집행 기록' 버튼으로만 늘어납니다.
- 가용 현금은 위 종목부터 차례로 나눠 씁니다. 여러 종목의 ③을 합쳐도 현금을 넘지 않습니다.
- 입력이 빠지면 ③은 미확인입니다(계획, 집행, 게이트, 부족분, 현금 중 하나라도 없을 때).

## 월적립 게이트 (결정 1)
| 유형 | 기준 | 실행가능 조건 |
|---|---|---|
| 코어 ETF | C2 | Today 게이트 실행가능, 또는 대기/관찰이면서 사유가 타이밍뿐(R/R, 과열/추격금지, 조건 확인 대기, 패턴, 돈흐름). 방어우선·데이터확인·레버리지 조건부는 차단 |
| 장기보유 개별주 | C1 | 실행가능만 |
| 스윙 | C1 | 실행가능만 |
| 레버리지 | C1 | 실행가능만. 레버리지 안전 조건은 이미 Today 게이트에 들어 있음 |

- 코어 ETF의 상위 시간대 추세훼손 예외(D)는 아직 넣지 않았습니다. 4단계 비교를 보고 결정한 뒤 넣습니다.
- 게이트는 같은 계좌 범위의 Today 기록만 씁니다. 그 기록의 가격 기준일이 자산관리 엔진 기록과 다르면 쓰지 않고 '게이트 미확인'으로 둡니다.
- 정찰 1/3: Today 사이징이 1/3 정찰이면, 그 달 ②가 ①의 1/3에 이르는 순간 ③은 0입니다. 다시 계산하거나 반복 실행해도 1/3을 넘지 않습니다.
- 이중 차감 방지: ③은 차감식이 아니라 min()입니다. 매수 후 보유를 갱신하면 부족분이 줄고 기록으로 ②도 늘어나지만, 두 번 빼지 않습니다.

## 저장 (옵션 C)
- SQL: `stock_lab_core/db_schema.py`의 `MONTHLY_DCA_CREATE_SQL`. 테이블이 없으면 앱이 SQL을 펼쳐 보여 줍니다.
- `monthly_dca_plans`: owner_email, account_scope(선택 계좌 집합, 예: `IRP|ISA|연금저축|일반`), month_key(KST YYYY-MM),
  ticker, holding_type, plan_version, plan_krw, multiplier, decision_code, signal_label, policy_version, confirmed_at.
  고유키는 (owner, scope, month, ticker, version)입니다.
  - '계획 확정'을 누르면 새 버전이 추가됩니다. 이전 버전은 지우거나 고치지 않습니다(자동 덮어쓰기 없음).
  - 신호 미확인 종목은 확정하지 않습니다.
  - 확정 계획이 있으면 신호가 사라져도 계획은 그대로 남고, ③만 0이 됩니다(신호 미확인 · 데이터확인).
- `monthly_dca_executions`: owner, scope, month, ticker, exec_date, amount_krw(>0), plan_version, exec_key, conditions(jsonb), policy_version.
  - (owner, exec_key)가 고유합니다. exec_key는 계좌범위|월|종목|날짜|신호키라서, 같은 신호를 같은 날 두 번 기록할 수 없습니다.
- 두 테이블 모두 insert 전용입니다. RLS는 owner_email = 로그인 이메일 조건의 select·insert만 허용하고, update·delete 정책은 없습니다.
  앱은 기존과 같이 service role로 씁니다.
- 계좌 범위는 보유수량·현금 해시가 아니라 선택 계좌 집합입니다. 매수 후 보유가 바뀌어도 확정 계획이 같은 범위로 남습니다.
  신호 유효성 검사는 2단계의 입력 해시를 그대로 씁니다.
