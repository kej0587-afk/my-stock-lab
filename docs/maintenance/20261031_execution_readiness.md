# 실행 안내 정합성

## 다음 단계의 우선순위

1. 같은 입력의 판정·자료·표시 정합성을 먼저 고정한다.
2. 그다음 같은 측정 ID와 냉/온 캐시를 구분해 시세·지표·외부자료 병목을 측정한다.
3. 동작이 고정된 경계부터 작은 단위로 리팩토링한다.

큰 파일은 유지보수 위험이지만, 파일 분리 자체가 조회 속도나 투자 정확도를
보장하지 않는다. 수천 개의 코드 테스트도 매매 전략의 수익성을 입증하지 않는다.
점수·가중치 변경은 별도의 당시 공개자료 재생과 표본 밖 성과 검증이 필요하다.

## 확인한 결함

- 운영 GOOGL 검토 파일의 시장 게이트는 방어우선인데 실행메모에는 `분할 가능`,
  1차조건에는 소액 추가 문구가 그대로 남았다.
- 정상 진입 fixture에서 MFI 키만 제거하면 1차 게이트는 실행가능이지만
  최종 체크는 핵심 자료 미확인으로 대기한다. 그런데 진입계획·종합서술은
  1차 게이트만 보고 진입 가능으로 표시했다. RSI/%B 키 누락도 같은 경로다.
- 지표가 `None`인 경우와 아예 키가 없는 경우의 1차 게이트 처리가 다르다.
  이번에는 기존 선별 규칙을 변경하지 않고 최종 체크 거절이 표시에서
  무시되지 않도록 연결했다. 1차 통과는 매매 허가가 아니다.

## 적용 범위

- `execution_readiness`는 기존 게이트와 이미 계산된 최종 체크를 소비하는
  표시 전용 모듈이다. 점수를 추가하거나 최종 체크를 다시 실행하지 않는다.
- 게이트 통과, 명시적 `execution_allowed=True`, 차단 0개, 핵심 누락 0개가
  함께 확인돼야 최종 검토 가능 상태다. 빈 요약·허용 필드 누락은 허용이 아니다.
- 오늘점검·전광판에는 현재 실행 안내를 별도 컬럼으로 연결한다.
  오늘점검의 원 실행메모와 1차조건은 기술 원계획 표와 검토 데이터에 보존한다.
- 정밀관측소의 상단은 최종 체크 완료 후 같은 결과로 갱신한다.
  진입계획·종합설명·보유 패널의 추가매수 설명도 표시용 사본을 사용한다.
- 원 후보등급, 점수, 판정문구, 가격·수량, 시장 방어 및 원 게이트는 변경하지 않는다.
  조건 해소 후 참고할 계획을 현재 실행 허용과 구분한다.
- 검토 ZIP에는 실행 준비 상태를 별도 저장하고 원 게이트와 비교 가능하게 한다.
  원 워크플로와 최종 체크 전체를 이 섹션에 다시 중복 저장하지 않는다.
- 외부 API·DB 호출, 인증·보유량·관심등록 저장 변경은 없다.

## 검증

- 지표 키 누락의 실제 최종 체크 → 진입계획 → 서사 → 검토 ZIP을 연결해 회귀 검증.
- 게이트/최종 체크 조합, 빈 요약, 잘못된 허용 타입, 차단·누락 보존,
  원본 불변, 재적용 안정성, 차단 해제 후 오래된 표시가 재차 차단하지 않는지 검증.
- 관련 테스트 438개 통과 후 전체 회귀 및 브라우저 점검을 수행한다.
- 전체 회귀 4,086개 통과, 1개 건너뜀, 하위 테스트 18개 통과(179.63초).
  이후 최종 결과만 있고 원 게이트가 없는 경계도 허용하지 않도록 보강하고
  관련 검사 357개도 통과했다(31.45초).
- 로컬 MSFT 화면과 다운로드 ZIP에서 같은 실행 보류 상태를 확인했다.
  원 게이트와 최종 체크를 따로 보존하며 오래된 모듈은 없었다.
- 안내 생성만의 로컬 마이크로 측정: 1,000행 약 1.9ms.
  전체 오늘점검의 실제 경과시간 측정이나 속도 개선 수치가 아니다.

## 남은 검증

- 돈흐름 원천과 현재 판정 가격의 거래일·만료 정책을 통합해야 한다.
- 1차 게이트가 통과한 후보와 최종 체크가 통과한 종목의 비율을 실제 실행
  이력에서 비교해야 한다. 전 종목 최종 체크에 추가 외부 호출을 무조건
  붙이는 방식은 피한다.
- 공급 시세·최신 공시·컨센서스의 전 종목 정확도를 이번 패치로 입증하지 않았다.
