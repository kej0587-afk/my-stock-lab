# 경제지표 컨센서스 대상월 표기(백로그 #13)

작성 2026-11-24 KST · 근거: 보고서 (61) 1244~1261행, 2026-11-24 상태 문서 13번.

## 문제

- 연결 규칙 자체는 이미 엄격했다: `consensus_key`가 지표·대상월·기준·단위·발표일(UTC)이 모두 같을 때만 붙인다.
  다른 달 설문을 넘겨 쓰는 경로는 없었다.
- 그런데 보고서 설명이 오해를 불렀다. PPI 2026-10 전년비 행에는 Trading Economics의 2026-10 예상치(6.6%)가 붙었는데,
  아래 설명은 고정 문구 "컨센서스 연결: 1개 · 2026-09 발표 당시 설문 · 사후 기사 검증(10/21)"이라
  9월 설문을 10월 실제치에 붙인 것처럼 읽혔다(이번 표에서 9월 기사 확인 설문은 한 건도 쓰이지 않음).
- 실시간 공개표 예상치에는 `forecast_period`가 저장되지 않아 표에 대상월이 보이지 않았다.

## 변경

- `economic_consensus._event`: 예상치에 대상월(`forecast_period`)을 함께 저장한다(연결 키의 대상월과 같은 값).
- `report_consensus.attach_economic_consensus`: 실제로 붙은 행마다 지표·대상월·기준·발표일·출처를 진단에 기록하고,
  기사 확인 설문을 실제로 쓴 행 수를 따로 센다.
- 보고서 설명(`report_evidence.consensus_connection_line`): 붙은 행마다 "지표 대상월 기준 ← 출처(대상월 · 발표일)"을 적는다.
  기사 확인 설문을 안 썼으면 "쓰지 않음"과 이유(대상월·발표일 일치 행 없음 / 같은 대상월 공급 예상치 우선)를 적는다.
- 표의 예상치 칸에 "· 대상월 YYYY-MM"을 덧붙인다.
- 연결 규칙, 수치, 서프라이즈 계산, 판정은 바꾸지 않았다.

  미사용으로 표시, 다른 달 예상치는 붙지 않음.
- 컨센서스·경제지표·근거·보고서 묶음 2606 통과, 기존 실패 3건(bok 달력, dart 화면, summary_ownership RAM 위치)은 main에서도 같은 실패.
