## 같은 입력 CSV 재생

개인 원본 4개 CSV와 전후 출력은 `cache/` 또는 사용자 Downloads에만 보관한다.
세부 종목 목록·수량·계좌명은 Git에 기록하지 않는다.

- 104 고유 종목 = 방어우선 102 + 데이터확인 2 + 실행가능 0.
  하드차단 2는 104 안의 부분집합이다.
- 기존 충돌 16행 → 자료·매칭 1 / 강한 후보·실행 보류 10 / 대상 범위 4 / 의도된 제외 1.
  파킹자산 지정은 사용자 확인을 사용했다. 티커만으로 파킹자산으로 추정하지 않는다.
- 데이터확인 2와 오류 플래그 1은 같은 집계가 아니다. 데이터 부족 보류와 판단 실패 경고를 구별한다.
- 원본 104행의 점수·게이트·금액·기술 원신호 프레임은 표시 처리 전후 동일.

| 코어 A | 강한 분할추매 | 실행 보류 · 시장방어 | 같은 기술 원신호 보존 | 0.19 |

## 이력의 범위와 제한

- 초기 로컬 감사는 이력 0건/원격 인증 401이었다. 이후 인증된 운영에서 기존 거래일 쌍 40건을 읽었다.
  모두 계좌 범위·관측 입력 정보가 없어 이번 비교에 사용할 과거 20쌍은 0건이다. 과거20일 비교 완료로 주장하지 않는다.
- 오래된 owner 전용 이력에 계좌/관측 맥락을 임의로 붙여 비교하지 않는다. 비교 불가하면 현재 상태만 표시.
- 앞으로 동일 계좌 범위의 섹터 선두·회복 관찰·실행 수·보유행동을 기존 개인 report_history에 함께 저장한다.
  동일 거래일 쌍은 갱신하며, 최대 20개 비교 가능한 거래일 쌍을 점검한다.
- 입력 변경/stale 또는 계산 당시 포트 맥락 미확인이면 비교·저장을 보류한다.
  달력상 전 거래일과 일치할 때만 `전 거래일과 동일`, 그 외는 `직전 저장 기준일`로 구별한다.
- 시황 저장도 새 계좌별 비교 입력을 보존한다. 실패한 원격 읽기 뒤 무조건 덮어쓰지 않는다.
  기존 저장소의 여러 브라우저 동시 쓰기 원자성은 보장하지 않는다.
