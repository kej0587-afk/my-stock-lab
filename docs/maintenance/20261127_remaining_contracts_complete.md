## 실제 발견된 연구 재생 문제

재생이 가변 문서를 참조하므로 기존 manifest의 프로토콜 해시와 달라져 중단됐다.
Windows CRLF는 기존 `sha()`에서 정규화하므로 원인이 아니며, 가격 파일의 해시는 모두 맞았다.

- `1acdeb00`의 원본을 `docs/research/soxl_intraday_20261127/protocol.md`로 복구했다.
  SHA256 `e171fce58f52e50679cc74268ea918a848f573ed101a32deaf70f9175890edad`가 기존 manifest와 정확히 일치한다.
- 새 수집은 프로토콜도 한 번 저장하며 덮어쓰기를 거부한다. 재생은 그 복사본을 검증한다.
- 현재 유지보수 문서, 시뮬레이션 규칙, 원본 가격, manifest는 그대로 두었다.
- 실제 offline replay의 coverage/trades/summary/quality/equity CSV5개 해시가 기존 결과와 모두 같다.
  검증된 거래0건, 과거 게이트 미재현 등의 연구 한계도 그대로다.

## 전체 검증과 운영 범위

Python3.11.9/pandas2.3.3/numpy1.26.4의 전체 suite를 코드 고정 `62f6c1a1`에서 실행했다.
`pytest tests -q -p no:cacheprovider --tb=line -rf` 결과 **10,382통과 / 0실패 / 1skip**,
subtest18통과, 경고86건, 756.25초. XML failures/errors 모두0이다.
skip은 기존 `test_post_close_paragraph_and_following_brief_are_separate_tables`의
`markdown_it` 미설치이며 새 skip/xfail은 추가하지 않았다. XML 총10401은 subtest18을 포함하므로
pytest의 일반 test 통과 수와 혼동하지 않는다. 경고는 dtype/downcast·날짜 파싱 등의 기존 경로다.
전체 suite 시간은 운영 계산 속도 개선 수치가 아니다. 증거는 ignored
`cache/resume_20261127/all_after.xml/log` 및 각 `*_contract.xml/log`, `soxl_protocol_replay/`.

실제 운영 화면/Cloud/Supabase를 새로 검증하거나 재부팅하지 않았다. 운영 코드가 바뀌지 않았으므로
기존 #121 화면 확인 기록은 재사용하되 이번 운영 확인으로 주장하지 않는다.
