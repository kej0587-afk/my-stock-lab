# 최종체크 원입력 감사와 화면 역할 정리

## 확인한 범위

- 기준 main `748fe63d`, 시작 시 미커밋 없음. 기존 점수·투자판정·금액·시장방어·월적립·L3·공급처 TTL은 변경하지 않았다.
- 이전 운영 ZIP의 자료 부족 12행: 구조/과열 체크 미재생 8, 해당 체크 재생됐으나 전체 주문 근거 부족 3, 가격 날짜/완료봉 정합성 미확인 1.
- ZIP에는 결과 CSV만 있고 당시 `today_observation_inputs` 전체 envelope/원자료형은 없다. 로컬 계좌 스냅샷도 없다. 따라서 운영 8건 모두의 원인이 자료형이라고 확정하거나 12건을 과거 입력으로 재분류하지 않았다.
- 원 엔진 `decision_signals._build_structure_and_accumulation_flags`의 NumPy 가격 비교가 `np.bool_`를 반환하는 경로를 재현했다. 관찰기의 `isinstance(value, bool)` 검사가 이를 거절해 구조·과열 체크 전체가 생략됐다. 운영 엔진의 판정 오류가 아니라 읽기 전용 관찰의 근거 누락이다.

## 수정

1. 저장된 `bool`/`np.bool_`만 관찰용 복사본에서 정상화한다. 문자열 True/False, 숫자 0/1, None은 플래그로 추정하지 않는다. 유한 숫자는 기존 정밀 화면처럼 float로 변환하며 불리언을 숫자로 인정하지 않는다.
2. 원가격입력ID가 없거나 다르면 재생하지 않는다. 누락 필드명·부적합 자료형을 기록한다. 구조/과열과 비중/보유 체크는 기존 순수 함수를 그대로 사용한다.
3. 기존 관찰표/CSV에 `시장모의_최종체크입력`, `시장모의_독립체크`를 연결했다. 매크로 차단을 다른 종목 조건의 차단으로 세지 않는다. 전체 주문가능액·예산·최종체크가 없으면 실행가능은 계속 미확인이다.
4. 새 화면이나 별도 레이더를 추가하지 않았다. 구 캐시의 기존 관찰을 보존하고 새 감사 2열만 `저장 당시 상세 감사 미보존`으로 표시한다. 새 감사 열이 없다는 이유로 복원 104행을 다시 미확인으로 바꾸거나 외부 조회를 하지 않는다. 새 전체 계산부터 새 감사가 적용된다.

## 중복 기능의 역할과 우선순위

| 영역 | 맡길 질문 | 기존 연결/중복 확인 | 처리 순서 |

중복 화면과 중복 외부 조회는 서로 다른 문제다. 현재 코드에 공유 경로가 존재한다는 사실만으로 실제 병목이 없다고 결론내리지 않는다. 반대로 접힌 그래프 호출을 발견했다는 이유만으로 지연의 주원인이라고 단정하지 않는다.
